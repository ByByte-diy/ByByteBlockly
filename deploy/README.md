# Web production deploy (SPA + WASM static host)

Production Angular build **не включає** WASM-файли — лише `cache-manifest.json`. Toolchain (~330 MB усіх bundle) завантажується з CDN або окремого static host за URL з manifest.

## Розміри bundle (cache-manifest.json)

| Bundle ID | Deploy dir | totalBytes | ≈ MB |
|-----------|------------|------------|------|
| `wasm-avr-328p` | `assets/wasm/avr-328p/v0.2.0-W1-…/` | 56 548 747 | ~57 |
| `wasm-avr-mega` | `assets/wasm/avr-mega/v1.0.0-W1-…/` | 83 516 146 | ~84 |
| `wasm-esp32` | `assets/wasm/esp32/vesp-v1.0.0/` | **191 638 977** | **~192** |

Сумарно ~**332 MB** для повного web compile (AVR + ESP32). ESP32 — найбільший tier (~184 MB lazy prefetch у браузері).

Джерело правди: `src/assets/cache-manifest.json` → поле `totalBytes` на bundle.

## angular.json (production)

```json
"ignore": ["wasm/**"]
```

У `dist/web/assets/` потрапляють i18n, іконки, **cache-manifest.json** — без `assets/wasm/**`. Без цього SPA bundle перевищить budgets і не має сенсу тягнути ~192 MB ESP32 у shell.

Dev (`ng serve`) WASM лежить у `src/assets/wasm/` і віддається локально.

## Pipeline

### 1. Збірка

```bash
npm run build:web
```

Послідовність:

1. `prepare:wasm-avr` (328p + Mega) + `prepare:wasm-esp` → `src/assets/wasm/{family}/{version}/`
2. Оновлення `src/assets/cache-manifest.json`
3. `ng build --configuration production` → `dist/web/` (без wasm blobs)

Перевірка після кроку 3:

```bash
npm run deploy:verify
```

### 2a. Один static host (SPA + WASM на тому ж origin)

```bash
npm run deploy:sync-wasm    # копіює src/assets/wasm/* → dist/web/assets/wasm/*
npm run deploy:verify -- --expect-wasm
```

Або одною командою:

```bash
npm run deploy:web
```

Деплойте весь `dist/web/` на Pages / nginx / S3+CloudFront.

### 2b. CDN / окремий bucket для WASM

1. `npm run build:web` → деплой **лише** `dist/web/` (SPA).
2. Окремо залийте `src/assets/wasm/` на static host з тим самим path prefix `/assets/wasm/…` (як у `baseUrl` у manifest).
3. Застосуйте Cache-Control з [`static-headers`](./static-headers) (Netlify: скопіюйте в `_headers`).

Клієнт резолвить URL відносно `document.baseURI`; для cross-origin CDN потрібен reverse proxy або однаковий path на CDN.

### Cache-Control

Файл [`static-headers`](./static-headers):

- `cache-manifest.json` — короткий TTL (60s), щоб клієнт бачив нові версії bundle
- `wasm-catalog.json` — 5 хв
- решта WASM/assets — `immutable`, 1 рік (versioned dirs `v…/` / `vesp-v1.0.0/`)

## Git — що не комітити

| Шлях | Причина |
|------|---------|
| `src/assets/wasm/avr-328p/` | Prepared bundle + `.o` / `.wasm` |
| `src/assets/wasm/avr-mega/` | Prepared bundle + precompiled `.o` |
| `src/assets/wasm/esp32/` | Prepared bundle + sketch closure `.o` |
| `src/assets/cache-manifest.json` | Regenerated by prepare |
| `dist/`, `deploy/out/` | Build artifacts |
| `.cache/` | Завантажені tar (wasm-toolchains) |

У репо лишається лише `src/assets/wasm/THIRD_PARTY_NOTICES.md` (legal). Після clone: `npm run build:web` або окремо `prepare:wasm-*`.

Prepare-скрипти: `src/wasm-avr/`, `src/wasm-esp/`.

## Скрипти

| npm script | Дія |
|------------|-----|
| `build:web` | prepare AVR+ESP32 + production ng build |
| `deploy:verify` | SPA має manifest, без WASM (або `--expect-wasm`) |
| `deploy:sync-wasm` | Копіює WASM у `dist/web/assets/wasm/` |
| `deploy:web` | build:web + sync + verify |
